# الحالة الحالية لمشروع YmPharma

**تاريخ التدقيق:** 2026-10-10 (توقيت الرياض)
**الحالة العامة:** غير جاهز للإطلاق الإنتاجي؛ لم تُثبت أي وحدة كاملة إنتاجياً في هذا التدقيق.
**طريقة التقييم:** مراجعة المستودع والترحيلات والاختبارات، مع بناء محلي وفحوص CI. هذا تقييم للشيفرة والأدلة الموجودة، لا إثبات تشغيل كل المسارات على الإنتاج.

## ملخص القرار

يوجد تطبيق بواجهات React/TanStack Start، وخدمات خلفية عبر Supabase/PostgreSQL، وإعدادات Capacitor وPWA، ومكونات للمخزون والشراء والتأمين والوصفات والذكاء الاصطناعي وERP. وجود المكونات لا يعني اكتمال رحلة العمل أو سلامة صلاحياتها. المراجعة كشفت مخاطر عزل مؤسسة وسلامة مخزون، وتعارضاً بين دور استدعاء checkout ومنح RPC في migrations.

أُنجز إصلاح Cloudflare محلياً مع بناء Worker وWrangler dry-run ومعاينة Workerd ناجحة؛ هو في PR #13 ولم يُنشر. على head `0a48c4c5` نجحت CI وCodeQL وworkflow `osv-scanner` الجديد، لكن check منفصل باسم `OSV-Scanner/OSV Security Scan` وWorkers Builds بقيا فاشلين؛ إعداد البناء المدَار لا يستخدم هدف Cloudflare. إصلاح تفويض DLQ في PR #14 لم يُدمج أو يُطبق على قاعدة البيانات. PR #15 لإصلاح عزل التأمين مفتوح؛ نجحت CI وCodeQL لكن فشل check Workers Builds الخارجي. لم يُدمج أي من الطلبات.

## بنية التطبيق المثبتة

- **الواجهة:** React وTypeScript مع TanStack Start/Router وVite. الجذر يعرّف `lang="ar"` و`dir="rtl"`، لكن اختبارات الوصول محدودة.
- **الخادم والبيانات:** Supabase Auth وPostgreSQL، مع مخططات `public` و`ym` و`ym_private` وترحيلات RLS وRPC و`SECURITY DEFINER`.
- **التشغيل:** هدف Node/Nitro وهدف Cloudflare Workers على فرع مستقل؛ توجد إعدادات Capacitor وPWA دون إثبات مزامنة Offline شاملة أو طباعة.
- **الاختبارات:** Vitest وTypeScript وESLint وبعض Playwright smoke tests. أغلبها وحدات أو فحوص مخططات SQL، لا اختبارات قاعدة بيانات أو قبول E2E للعمليات.

| التأمين | مكسور على `main` | شركات وخطط ووثائق ومطالبات ودورة قرار/دفع خلفية | upserts غير مقيدة بالمؤسسة على `main`؛ PR #15 يضيف scope وعلاقات المؤسسة، لكن لم يُدمج أو يُختبر على DB حية |
| الوصفات والرعاية السريرية | جزئي | وصفات منظمة وصرف وباركود وبعض الفحوص | OCR منفصل عن الوصفة المنظمة؛ لا طابور HITL مكتمل وبعض السياقات تمر كـ`null` |
| المتجر والطلبات | جزئي | كتالوج عام وسلة وطلبات ورفع إيصال | لا إلغاء/تتبع شحن أو بوابة دفع؛ ربط ERP غير مثبت؛ التدفق ليس POS |

| التقارير | جزئي | تحليلات تنفيذية خلفية محمية جزئياً وCSV محدود | واجهة التقارير محاكاة؛ لا تقارير فعلية مكتملة للمالية والمخزون والتأمين والشراء |
| تجربة الاستخدام والوصول | جزئي | RTL عربي، مكونات حالات واستجابة جزئية | لا axe/تباين/keyboard؛ عناصر ونافذة محادثة تفتقد دلالات وصول |
| الذكاء الاصطناعي | جزئي | Agent Runtime وسياسات وسلامة وطلبات موافقة مخزنة | واجهة HITL غير مكتملة؛ إجراءات سريرية لا تتطلب دائماً موافقة؛ `/ai-chat` بيانات demo ثابتة |
| التشغيل والمراقبة | جزئي | CI وerror sink وجداول تنبيه ونسخ احتياطي مجدول | لا استعادة/rollback مثبتين أو نشر Worker وفحص post-deploy أو دليل وصول التنبيهات |
| الأمن والهوية | جزئي | Auth وRBAC وRLS واسع وسجل تدقيق | عزل الفروع غير مكتمل؛ اعتماد على service-role؛ اختبارات DB قد تُتخطى |

## تغييرات هذه المهمة

1. فُصل بناء Node عن Cloudflare، وأضيف `@cloudflare/vite-plugin` ومدخل TanStack الرسمي و`build:cloudflare` و`validate:cloudflare` وWrangler dry-run. الأدلة في `../deployment/CLOUDFLARE-10021-REPAIR.md`.
2. PR #14 يضيف ترحيلاً يقيد `public.agent_events_dlq_stats()` بمدير مخول أو `service_role` واختباراً؛ لم يدمج ولم يطبق على Supabase الحية.
3. OSV v1.9.0 فشل برسالة `No package sources found` مع `bun.lock`، لا نتيجة ثغرة. reusable workflow الرسمي v2.6.0 نجح في check `osv-scanner` على PR #13، لكن check منفصلاً `OSV-Scanner/OSV Security Scan` ما زال فاشلاً.
4. PR #15 يقيد تحديثات التأمين بـ`organization_id` ويتحقق من ملكية provider/patient/plan قبل الكتابة، مع اختبارات محلية. نجحت CI وCodeQL؛ بقي Workers Builds فاشلاً. التغيير غير مدمج وغير مختبر على قاعدة فعلية.
5. أُعدّت وثائق الحالة والخطة والهندسة والاختبارات والأمن والجاهزية والاستمرارية ضمن هذا المجلد.

## ما لم يحدث

لم يُدمج أي PR، ولم يتغير `main` أو DNS أو Worker الإنتاجي. لم تُطبق migrations على قاعدة حية، ولم تُقرأ بيانات أعمال أو أسرار، ولم تُنفذ اختبارات قبول على staging/production. لم يتم شراء أو إرسال أو تعديل حساب خارجي.
