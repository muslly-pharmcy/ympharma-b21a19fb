# ربط الموقع بالمشروع المختار

المشروع المعتمد بتوجيه المالك: `ybhrmcdlgyccywpmiucz`، وعنوانه `https://ybhrmcdlgyccywpmiucz.supabase.co`.

## الإعداد الفعلي

هوية الاتصال العامة في `config/public-backend.ts`. تحتوي العنوان والمعرّف والمفتاح **العام فقط**. يثبّت البناء هذه القيم وتقرأها واجهات الخادم والمتصفح وCSP وMCP بصورة متطابقة؛ قيم Lovable Cloud المحجوزة المرتبطة بالمشروع القديم لا تستبدل اختيار المالك. عند تدوير المفتاح العام حدّث هذا المصدر وأعد البناء واستخراج MCP manifest.

يصدر الخادم قيمتين عامتين فقط في JSON مهرب قبل Scripts. العملاء ينشؤون عند الاستخدام، والجلسة والكتالوج المخزن محليًا معزولان حسب المشروع. إتمام الطلب يحتفظ بواجهة `checkout_cart_fefo` الأصلية ذات المعاملات الستة؛ لم يُغيّر المخطط أو المال أو المخزون.

## المفتاح الخاص بالخادم

الوظائف الإدارية وتوقيع الصور الخاصة تحتاج مفتاحًا من **المشروع المختار نفسه**. أضف عبر إعدادات الأسرار الآمنة في Lovable:

```env
MUSLLY_SUPABASE_PROJECT_ID=ybhrmcdlgyccywpmiucz
MUSLLY_SUPABASE_SERVICE_ROLE_KEY=
```

املأ القيمة الثانية داخل مدير الأسرار فقط. يقبل الخادم مفتاح `sb_secret_` أو مفتاح service_role قديمًا يطابق معرّف المشروع. لا تستخدم مفتاحًا عامًا هنا ولا تضع أسرارًا في `VITE_` أو Git أو المحادثة. الربط المحجوز السابق لا يُستخدم للعمليات الإدارية. غياب الربط الصحيح يعطل تلك العمليات؛ تصفح الكتالوج يبقى بالمفتاح العام وتطبق عليه RLS.

## التحقق

```sh
bun install --frozen-lockfile
bunx tsc --noEmit
bunx eslint . --max-warnings=0
bun run test
bun audit
bun run build
E2E_MOCK_SERVER=1 bunx playwright test e2e/connection-repair.e2e.ts
bun run validate:cloudflare
```

اختبارات المتصفح في CI تستخدم خادم بيانات اصطناعية؛ لا تنشئ حسابات أو طلبات أو تراسل العملاء. تحقق مستقل على المعاينة يتضمن المنتجات والبحث والتصفح والمساعد وhealth ومصدر المصادقة وصفحة offline. اختبارات RLS التي تحتاج قاعدة تجربة حقيقية يجب تمييزها إذا تخطتها البيئة، ولا يُعتبر التخطي نجاحًا أمنيًا.

## الإصدار

ادمج النسخة المصححة واجعل Lovable يبني نفس commit الذي اجتاز الاختبارات، ثم تحقق من `https://muslly.com/api/public/health` ومن hydration وواجهة الكتالوج واتصالات المتصفح للمضيف المختار. اختبر تسجيل الدخول بحساب اختبار معتمد وإتمام طلب على بيئة تجربة قبل إعلان نجاح رحلة الشراء؛ ظهور نموذج الدخول واستجابة Auth settings لا يثبتان تلك الرحلة.

المراجعة المستقلة وجدت أخطاء بناء وتوجيه استيراد في commit `7591611f1ce743569696bc1cd0e3f795722e407e`؛ **لا تنشر ذلك الالتزام قبل تطبيق تصحيحات هذه الحزمة**. حُلّ عائق الكتابة بتثبيت موصل GitHub على منظمة المستودع، ودُمج الإصلاح في PR #22 ثم نُشر الالتزام `92ba11c734921fc92628c33a77ea7a270d1e8edb` عبر Lovable في 27 أكتوبر 2026. نجح التحقق المستقل من الموقع المنشور في 19 فحصًا على الكمبيوتر والجوال، تشمل الكتالوج والبحث وفتح المساعد وhealth وMCP وصفحة offline. لم تُختبر معاملات فعلية أو تسجيل دخول بحساب مستخدم.

إذا استُخدم تكامل Cloudflare Workers Builds المنفصل، يختار البناء محول Worker تلقائيًا عند `WORKERS_CI=1`؛ البناء المعتاد خارج هذه البيئة يبقى Node/Nitro. يبقى الأمر الصريح `bun run build:cloudflare` متاحًا. أوامر البناء والنشر الفعلية وصلاحيات ذلك التكامل تدار في لوحة Cloudflare، ولا يثبت نجاح dry-run المحلي صحة إعدادات الحساب الخارجية.

ربط `www.muslly.com` يتطلب إعداد Domains في Lovable وشهادة صالحة. لا تغيّر سجلات DNS بالتخمين. أبقِ ERP والكتابة القديمة لـOracle معطلين، ولا تطبق ترحيلات الأسعار والمخزون السابقة ضمن هذا الإصدار.
