# تسجيل مرضى مبسّط: اسم ثلاثي + هاتف + كلمة مرور (بدون OTP)

## ما هو قائم فعلياً (تم فحصه)
- `src/routes/auth.tsx` صفحة متعددة الخطوات: الاسم → اختيار طريقة → بريد/كلمة مرور، وخطوات هاتف/OTP معطّلة خلف مفتاح `enable_phone_auth`.
- التحقق من الاسم في `src/lib/auth/patient-name.ts` والهاتف في `src/lib/auth/phone.ts` (تطبيع E.164 مع 967+) — جاهزان ويُعاد استخدامهما كما هما.
- هوية المريض في `src/lib/patient-identity.functions.ts`: صف واحد في `public.hc_patients` مرتبط بـ `user_id` (يحتوي `phone` و`email`). لا يوجد جدول `public.patients`.

## التدفق الجديد (شاشة واحدة)
1. الاسم الأول / اسم الأب / اسم العائلة (إلزامي) مع معاينة الاسم الكامل.
2. رقم الهاتف ‎+967 (إلزامي) — **بدون أي رمز تحقق**.
3. كلمة المرور (إلزامية، 8 أحرف فأكثر) — لأن الرقم وحده لا يصلح كمُعرّف آمن.
4. صورة البطاقة التأمينية (اختيارية): رفع ملف أو التقاط بالكاميرا، ويمكن التخطي.
5. زر «🚀 إنشاء الحساب والدخول» → إنشاء الحساب وفتح الجلسة فوراً → تحويل مباشر إلى لوحة المريض `/patient-profile`.

تسجيل الدخول: رقم الهاتف + كلمة المرور في نفس الصفحة. الدخول بالبريد يبقى كما هو لمن لديه حساب بريدي (لا نكسر شيئاً قائماً).

### كيف تعمل الجلسة بلا OTP
يُنشأ الحساب في نظام المصادقة ببريد داخلي مشتق من الرقم بصيغة `967XXXXXXXXX@phone.muslly.com` مع كلمة مرور المريض، والرقم يُحفظ في `profiles` و`hc_patients`. الدخول لاحقاً بالرقم يُترجم لنفس البريد الداخلي. يتطلب هذا تفعيل «تأكيد الحساب التلقائي» في إعدادات المصادقة (وإلا لن تُفتح الجلسة فوراً).

آثار جانبية سأصرّح بها للمستخدم: استعادة كلمة المرور بالبريد لن تعمل لحسابات الهاتف؛ الاسترجاع يتم عبر الطاقم حتى يُفعَّل مزوّد رسائل.

## قاعدة البيانات والتخزين (هجرة واحدة + إنشاء حاوية)
- `ALTER TABLE public.hc_patients ADD COLUMN IF NOT EXISTS insurance_card_url TEXT` (حقل `phone` موجود مسبقاً — لا عمود جديد له).
- إنشاء حاوية خاصة `insurance-cards` (غير عامة) عبر أداة التخزين.
- سياسات على `storage.objects` لحاوية `insurance-cards` فقط:
  - المريض يرفع/يقرأ/يحذف ملفاته داخل مجلد باسم `auth.uid()`.
  - طاقم الصيدلية (`has_role(auth.uid(),'admin')` أو عضوية المؤسسة) يقرأ فقط.
- لا حذف بيانات، ولا مساس بجداول أو سياسات أخرى.

## الكود
- `src/lib/auth/phone.ts`: إضافة `phoneToAuthEmail()` (اشتقاق البريد الداخلي) فقط — دون تغيير المنطق القائم.
- `src/routes/auth.tsx`: إعادة تصميم خطوة التسجيل إلى نموذج واحد RTL محسّن للجوال (320–414px) بالترتيب المطلوب، مع إبقاء `safeRedirect` ورسائل الأخطاء العربية كما هي.
- مكوّن رفع بطاقة تأمين (اختياري) يرفع الملف بعد فتح الجلسة إلى `insurance-cards/{uid}/…` عبر عميل Supabase القائم.
- `src/lib/patient-identity.functions.ts`: قبول `phone` و`insuranceCardPath` اختيارياً وحفظهما على الصف الواحد للمريض (بدون تكرار سجلات، وبدون مطابقة بالاسم).
- بدون أي تعديل على نواة الذكاء الاصطناعي أو Control Tower أو أدوات الجلسة القائمة.
