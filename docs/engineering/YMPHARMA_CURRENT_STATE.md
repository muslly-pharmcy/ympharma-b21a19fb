# الحالة الحالية لمشروع YmPharma

**تاريخ التدقيق:** 2026-10-10 (توقيت الرياض)  
**الحالة العامة:** غير جاهز للإطلاق الإنتاجي. لا توجد وحدة مكتملة ومثبتة إنتاجياً في هذا التدقيق.  
**طريقة التقييم:** مراجعة المستودع والترحيلات والاختبارات، مع بناء محلي وفحوص CI. نتائج الوحدات أدناه هي تقييم للشيفرة والأدلة الموجودة، لا إثبات تشغيل في بيئة الإنتاج.

## ملخص القرار

يوجد تطبيق فعلي بواجهات React/TanStack Start، وخدمات خلفية عبر Supabase/PostgreSQL، ومسارات أصلية لـCapacitor وPWA، وتكاملات جزئية للمخزون والشراء والتأمين والوصفات والذكاء الاصطناعي وERP. وجود هذه المكونات لا يعني اكتمال رحلة العمل أو سلامة صلاحياتها. التدقيق الساكن كشف مسارات حرجة قد تسمح بخرق عزل مؤسسة أو إفساد رصيد مخزون، كما كشف تعارضاً بين صلاحية checkout والمنح في أحدث migrations.

أُنجز إصلاح منفصل لمسار Cloudflare محلياً، مع بناء Worker وWrangler dry-run ومعاينة Workerd ناجحة. التغيير محفوظ في PR #13 للمراجعة، ولم يُنشر. الإصلاح الأمني لدالة إحصاءات DLQ محفوظ في PR #14، ولم يُطبّق على قاعدة البيانات الحية. فحوص Workers Builds الخارجية ما زالت تفشل مع إعدادات البناء المدارة، كما فشل OSV Scanner 1.9.0 لأنه لم يجد مصدر حزم مناسباً لملف `bun.lock`. جرى تحديث workflow محلياً إلى reusable workflow الرسمي v2.6.0 الداعم لفحص Bun؛ نتيجة CI لذلك التحديث معلّقة حتى وصوله إلى GitHub.

## بنية التطبيق المثبتة

- الواجهة: React وTypeScript مع TanStack Start/Router وVite. الجذر يعرّف `lang="ar"` و`dir="rtl"`، لكن اختبارات الوصول والتصميم الشامل محدودة.
- الخادم والبيانات: Supabase Auth وPostgreSQL، مع مخططات `public` و`ym` و`ym_private`، وترحيلات RLS وRPC و`SECURITY DEFINER`.
- التشغيل: هدف Node/Nitro قائم، وهدف Cloudflare Workers أُضيف له تكامل Vite الرسمي على فرع مستقل. توجد إعدادات Capacitor وPWA، لكنهما لا يثبتان مزامنة تشغيلية كاملة أو طباعة.
- الاختبارات: Vitest وTypeScript وESLint وبعض Playwright smoke tests. معظم الاختبارات وحدات نقية أو تحقق من مخططات/نصوص migrations، وليست اختبارات قاعدة بيانات أو قبول end-to-end للعمليات.

## خريطة اكتمال الوحدات

| الوحدة | التقييم | ما ثبت وجوده | الفجوة الأهم |
|---|---|---|---|
| الكتالوج | جزئي | قراءة عامة للمنتجات المعتمدة، CRUD خلفي، واستيراد SBDMA/Excel | حقول دوائية ووحدات غير مكتملة، ولا uniqueness عالمي للباركود أو بدائل علاجية معتمدة |

| المحاسبة | جزئي | دفتر فوترة محدود ولوحة مالية بسيطة | استعلام يطلب أعمدة غير موجودة في `billing_ledger`؛ لا محاسبة مزدوجة أو إقفال/تسويات أو دقة 4 منازل |
| التأمين | مكسور | شركات وخطط ووثائق ومطالبات ودورة قرار/دفع خلفية | عمليات upsert بعميل service-role مقيّدة بـ`id` فقط دون `organization_id`؛ قابلية تحديث عبر المؤسسات |
| الوصفات والرعاية السريرية | جزئي | وصفات منظمة وصرف ومراجعة باركود وبعض فحوص سريرية | التقاط/OCR منفصل عن الوصفة المنظمة، لا طابور HITL متكامل للوصفة، وسياقات سريرية أساسية تمر كـ`null` |
| المتجر والطلبات | جزئي | كتالوج عام، سلة، طلبات، ورفع إيصال | لا إلغاء/تتبع شحن، ولا بوابة دفع؛ ربط ERP بالطلب غير مثبت؛ التدفق ليس POS |

| التقارير | جزئي | تحليلات تنفيذية خلفية محمية ببعض الصلاحيات وCSV محدود | واجهة التقارير العامة محاكاة؛ لا مصدر فعلي لتقارير المالية/المخزون/التأمين/المشتريات |
| تجربة الاستخدام والوصول | جزئي | RTL عربي، مكونات حالات، وتصميم متجاوب جزئياً | لا اختبارات axe/تباين/keyboard؛ عناصر أيقونية ونافذة محادثة تفتقد دلالات وصول أساسية |
| الذكاء الاصطناعي | جزئي | Agent Runtime وسياسات وأدوات وسلامة وطلبات موافقة مخزنة | لا مسار واجهة قرار HITL مكتمل؛ بعض الإجراءات السريرية لا تتطلب موافقة تلقائية؛ `/ai-chat` يعرض بيانات تجريبية ثابتة |
| التشغيل والمراقبة | جزئي | CI للبناء والاختبارات، error sink، جداول تنبيه ونسخ احتياطي مجدول | لا استعادة/rollback مثبتين، ولا نشر Worker أو فحص post-deploy أو دليل وصول التنبيهات |
| الأمن والهوية | جزئي | مصادقة، RBAC وRLS واسع، وسجل تدقيق خلفي | عزل الفروع غير مكتمل، مسارات تعتمد service-role، اختبارات DB قد تُتخطى، وواجهات الأمن ليست لوحة مراقبة حية |

## تغييرات هذه المهمة

1. فُصل بناء Node عن Cloudflare، وأضيف `@cloudflare/vite-plugin` ومدخل TanStack Start الرسمي مع `build:cloudflare` و`validate:cloudflare` وWrangler dry-run. الأدلة التفصيلية في `../deployment/CLOUDFLARE-10021-REPAIR.md`.
2. أضيف في PR #14 ترحيل يقيد `public.agent_events_dlq_stats()` بمدير مخول أو `service_role`، مع اختبار انحدار. لم يُدمج ولم يُطبّق على Supabase الحية.
3. أُعيدت معالجة OSV: الإصدار `v1.9.0` فشل برسالة `No package sources found` مع `bun.lock`، وليس بسبب نتيجة ثغرة موثقة. جرى تحديث workflow محلياً إلى reusable workflow الرسمي `v2.6.0`، ونتيجة فحص هذا التحديث لم تُعتمد بعد.
4. أُعدّت وثائق الحالة والخطة والهندسة والاختبارات والأمن والجاهزية والاستمرارية ضمن هذا المجلد.

## ما لم يحدث

لم يُدمج أي PR، ولم يتغير الفرع الرئيسي أو DNS أو Worker الإنتاجي. لم تُطبّق migrations على قاعدة بيانات حية، ولم تُقرأ بيانات أعمال أو أسرار. لم تُنفذ اختبارات قبول على staging/production، ولا تم شراء أو إرسال أو تعديل حساب خارجي.
