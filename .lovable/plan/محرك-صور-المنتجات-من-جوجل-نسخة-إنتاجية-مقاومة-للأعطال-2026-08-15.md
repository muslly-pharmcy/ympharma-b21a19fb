# محرك صور المنتجات من جوجل — نسخة إنتاجية مقاومة للأعطال

تحديث `src/lib/ai/product-image-search.functions.ts` فقط (مع تعديل بسيط على واجهة `/admin-image-queue` لعرض المقاييس الجديدة).

## 1. تعدد مفاتيح جوجل والتبديل التلقائي
- قراءة المفاتيح داخل الـ handler من `GOOGLE_API_KEYS` (JSON array أو نص مفصول بفواصل) ثم `GOOGLE_API_KEY` (يدعم قيمة واحدة أو عدة قيم مفصولة بفواصل)، مع إزالة الفراغات والتكرار.
- نفس المنطق لمعرّف محرك البحث: `GOOGLE_SEARCH_ENGINE_ID` / `GOOGLE_CSE_ID` / `GOOGLE_CX_ID`.
- مؤشر مفتاح حالي داخل الدفعة: عند رد 429 أو 403 من نوع تجاوز الحصة (`quotaExceeded` / `rateLimitExceeded` / `dailyLimitExceeded`) يُعلَّم المفتاح كمستهلك ويُعاد المحاولة فوراً بالمفتاح التالي دون فقدان المنتج.
- 403 من نوع "API غير مفعّل / مفتاح غير صالح" لا يُعتبر حصة: يُعلَّم المفتاح كمعطوب وينتقل للتالي، ورسالة عربية واضحة.
- عند نفاد كل المفاتيح: تتوقف الدفعة بهدوء وتُرجَع بقية المنتجات كـ `quota` بدون رمي استثناء.

## 2. إعادة المحاولة والمرونة
- backoff أسّي مع jitter (حتى 3 محاولات) لأخطاء الشبكة و429 و5xx عبر `retryAsync` الموجود في `src/lib/net/retry.ts`.
- لا استثناءات صلبة: أي فشل لمنتج واحد يُسجَّل كـ `skipped` مع السبب وتستمر الدفعة.

## 3. استراتيجية البحث والترتيب
- الاستعلام الأول: `"{اسم المنتج} دواء علبة"`، والثاني عند عدم وجود نتيجة: `"{اسم المنتج} صيدلية"`.
- تصفية الامتدادات `.jpg/.jpeg/.png/.webp` وHTTPS فقط، واستبعاد الصور الأصغر من 200px.
- الترتيب بأعلى دقة (العرض × الارتفاع) مع أفضلية للنطاقات الصيدلانية/الطبية الموثوقة (القائمة الحالية `PREFERRED_HOSTS`).

## 4. الإيقاف والمقاييس
- استقبال إشارة الإلغاء داخل الخادم عبر `getRequest().signal` وتمريرها إلى كل `fetch` وإلى انتظار الـ backoff؛ عند الإلغاء تتوقف الحلقة فوراً وتُرجَع النتائج المتراكمة بدل رمي خطأ.
- شكل الإرجاع الجديد:
```text
{ processed, updated, skipped, remaining, aborted,
  reasons: { quota, noImage, stopped, error },
  keysUsed, results[] }
```
- تحديث بطاقة التقرير في `/admin-image-queue` لعرض: الإجمالي، الناجح، المتخطّى بسبب الحصة، بلا صورة، الإيقاف اليدوي.

## ملاحظات تقنية
- قراءة `process.env` داخل الـ handler فقط، واستيراد `client.server` بشكل كسول — كما هو الآن.
- يبقى الحارس `assertAdmin` (admin/owner) والتسجيل عبر `recordAiCall` تحت الميزة `product-image-search`.
- لا تغيير على `catalog_product_media` ولا على منطق التسعير أو المخزون.
- تذكير: الحالة الحالية أن Custom Search API يرجع 400/403؛ التبديل بين المفاتيح لن ينفع قبل تفعيل الـ API على المشروع في Google Cloud.
